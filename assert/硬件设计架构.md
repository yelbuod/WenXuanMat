# 硬件设计架构

## 部分松耦合

分为几点原因

1. xuantie matrix 指令集存在部分需要写入rd的指令, 因此如果在具备重命名技术的处理器上进行扩展, 例如C910, 就必须经过其IR阶段的重命名逻辑, 为指令rd分配物理寄存器. 后续可能可以优化, 例如只为需要写入GPR的指令进入IR stage并分配物理寄存器, 其他的直接发送到matrix entries.
2. 编译工具链编译结果存在普通指令和矩阵指令混用, 因此如果采用完全解耦的方式, 预估效率可能较低.

## 异常指令处理

可能引发异常的指令:

1. Matrix Size Configuration的`sizeK` 如果不是`element size in byte`的整数倍则引发**非法指令异常**.
   但是是先配置`sizeK`才会有后续ALU/LSU指令内包含关于`element size`的配置?
2. 定义在`mstatus`, 影射在`sstatus`, 与`FS/VS/XS`类似的, 表示矩阵指令集状态的`MS`位域, 如果在设置为`2'b00(All off)`时执行任意矩阵指令和访问任意矩阵CSR时会引发**非法指令异常**.
3. `fcsr`的浮点dynamic rounding mode设置为无效值, 则任意带dynamic rounding mode的浮点操作会引发**非法指令异常**.
4. 定义在`mstatus`的表示浮点状态的`FS`如果设置为`off`, 任意矩阵浮点指令的执行会引发**非法指令异常**.
5. 浮点运算相关会引发**无效操作异常**.

2/3/4都可以在译码阶段触发异常? 但是又要考虑前面有预测中的分支指令?
